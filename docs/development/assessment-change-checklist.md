# Assessment change checklist

## Capability

- [ ] Stable ID exists and is preserved.
- [ ] Definition tests one coherent capability and business outcome is clear.
- [ ] Applicability and foundational rationale are defined.
- [ ] Primary category and secondary relationships are assigned without duplicate scoring.
- [ ] Status distinguishes taxonomy inclusion, implementation, validation, and activation.

## Questions

- [ ] One concept; observable answer states; no compound wording.
- [ ] Unknown is distinct from absent and N/A is supported where necessary.
- [ ] Wording is understandable and does not assume company size/vendor.
- [ ] Scoring interpretation, evidence requirement, and compatibility impact are documented.

## Findings and recommendations

- [ ] Finding conditions match observable evidence and severity is justified.
- [ ] Critical threshold is met; uncertainty is not overstated.
- [ ] Recommendations and mapping IDs are valid and actionable.

## Scoring and standards

- [ ] Formula impact and worked examples are reviewed.
- [ ] Historical assessments will not silently change; version impact is classified.
- [ ] Framework version, specific reference, relationship, and source review are identified.

## Release

- [ ] Manifest validates; `npm test` and `npm run build` pass.
- [ ] Active version and migration path are correct.
- [ ] Documentation, traceability, and known limitations are updated.
