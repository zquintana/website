# Standards mapping

The active framework list includes NIST CSF 2.0, CIS Controls, CIS Benchmarks, Microsoft and Google security guidance, AWS/Azure/GCP architecture frameworks, ITIL, ISO 22301, ISO 27001 concepts, FinOps, and OWASP. These are contextual references, not certification claims.

Mappings are `direct`, `partial`, or `supporting` relationships attached to capabilities or recommendations. A useful mapping must include standard ID, framework name and version, publisher, specific reference, relationship, notes, source URL, and last-reviewed date. The current `StandardDefinition` lacks required source/review fields for most entries and many mappings use broad prose references; this is provisional.

Product-specific recommendations must remain separate from vendor-neutral capability definitions. Framework names alone are insufficient evidence and a mapping never implies compliance. Obsolete framework versions should remain addressable for historical reports and be marked deprecated; new methodology versions should use the current reference after review.
